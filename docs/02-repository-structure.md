# 📂 02 - Repository Structure

Understanding the repository structure is one of the first steps toward becoming an efficient software engineer.

A well-organized repository makes it easier to:

- Find files quickly
- Collaborate with teammates
- Maintain code
- Scale projects
- Automate workflows

This guide explains every folder and file you'll encounter during the semester.

---

# 📁 Repository Overview

Your repository will look similar to this.

```text
leetcode-lab-yourname-rollnumber/
│
├── .github/
├── challenges/
├── docs/
├── resources/
├── templates/
│
├── README.md
├── CONTRIBUTING.md
├── CHANGELOG.md
├── CODE_OF_CONDUCT.md
├── LICENSE
├── requirements.txt
└── .gitignore
```

Each folder has a specific purpose.

---

# 📁 .github/

This folder contains GitHub-specific configuration files.

Example

```text
.github/

├── workflows/
├── ISSUE_TEMPLATE/
└── PULL_REQUEST_TEMPLATE.md
```

These files help automate tasks inside GitHub.

Examples include

- GitHub Actions
- Pull Request Templates
- Issue Templates

### Students Should

✅ Read Pull Request Templates

❌ Do not modify GitHub workflow files.

---

# 📁 challenges/

This is the most important folder in the repository.

Every coding challenge released during the semester will be placed here.

Example

```text
challenges/

├── week-01/
├── week-02/
├── week-03/
└── week-04/
```

Each week contains multiple coding problems.

Example

```text
week-01/

├── lc-0001-two-sum/
├── lc-0125-valid-palindrome/
└── lc-0242-valid-anagram/
```

---

# 📁 Inside a Challenge

Each challenge has its own folder.

Example

```text
lc-0001-two-sum/

├── README.md
├── starter.py
├── test_solution.py
├── hints.md
├── editorial.md
└── assets/
```

Every file has a purpose.

---

## README.md

Contains

- Problem statement
- Examples
- Constraints
- Expected output

Always read this file first.

---

## starter.py

Contains the starter code.

This is where you will write your solution.

Example

```python
class Solution:

    def twoSum(self, nums, target):
        pass
```

Students SHOULD edit this file.

---

## test_solution.py

Contains automated unit tests.

These tests verify whether your solution is correct.

Students should never edit this file.

---

## hints.md

Contains hints provided by the instructor.

Read this only if you get stuck.

---

## editorial.md

Contains

- Explanation
- Optimized solution
- Alternative approaches

This file is usually released after the submission deadline.

---

## assets/

Contains

- Images
- Flowcharts
- Diagrams

Students normally do not modify this folder.

---

# 📁 docs/

Contains all documentation for this repository.

Example

```text
docs/

├── README.md
├── 01-getting-started.md
├── 02-repository-structure.md
├── 03-solving-your-first-challenge.md
├── 04-git-workflow.md
```

---

# 📁 resources/

This folder contains reference material to help you learn.

Examples

```text
resources/

├── python-cheat-sheet.pdf
├── git-cheat-sheet.pdf
├── time-complexity.pdf
└── interview-notes.pdf
```

Use these resources whenever needed.

---

# 📁 templates/

Contains reusable templates maintained by the instructor.

Example

```text
templates/

├── challenge-template/
├── notes-template.md
└── starter-template.py
```

Templates ensure that every challenge follows the same structure.

Students should never edit files inside this folder.

---

# 📄 Root Files

The root directory contains several important files.

---

## README.md

The main page of the repository.

It explains

- Repository overview
- Quick Start
- Documentation links
- Rules

Read this before starting.

---

## CONTRIBUTING.md

Explains how students should contribute to the repository.

Topics include

- Branch naming
- Commit messages
- Pull Requests

---

## CHANGELOG.md

Contains the history of important updates made to the repository.

Read this to know what has changed.

---

## CODE_OF_CONDUCT.md

Defines expected professional behaviour.

Treat everyone respectfully while collaborating.

---

## LICENSE

Specifies how this repository may be used.

Students usually do not need to modify this file.

---

## requirements.txt

Lists the required Python packages.

Install them using

```bash
pip install -r requirements.txt
```

---

## .gitignore

Tells Git which files should not be tracked.

Example

```text
__pycache__/

.venv/

.vscode/
```

Students usually do not edit this file.

---

# ✏️ Files You Should Edit

During the semester, you will primarily work on your solution files.

Examples

```text
starter.py

solution.py

notes.md
```

Only modify files that are explicitly mentioned in the challenge instructions.

---

# 🚫 Files You Should Never Edit

Do not modify

```text
test_solution.py

README.md (inside challenge folders)

editorial.md

templates/

.github/

requirements.txt
```

Changing these files may cause your submission to fail or behave unexpectedly.

---

# 📌 Best Practices

As you work on challenges:

- Read the challenge completely before coding.
- Keep your repository organized.
- Do not rename folders or files.
- Do not delete project files.
- Commit your work regularly.
- Pull the latest changes before starting a new challenge.

---

# 🧠 Think Like a Software Engineer

Professional developers spend time understanding a project's structure before writing code.

Whenever you join a new project:

1. Explore the repository.
2. Read the documentation.
3. Understand the folder structure.
4. Identify the files you need to modify.
5. Begin implementing your solution.

Developing this habit will help you work efficiently on larger software projects.
